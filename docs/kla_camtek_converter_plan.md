## 0. 한눈에 보기

**지키는 원칙 3가지**
1. **간단하게**: 제조 화면은 3단계(Lot 고르기 → 확인 → 업로드). 설정·경로 입력은 제조가 하지 않음
2. **원본 파일은 절대 훼손하지 않음**: 원본은 읽기 권한으로만 열고, 쓰기는 업로드 폴더에만 (6.1)
3. **잘못된 맵은 올라가지 않게**: 누적 맵이 틀리면 이후 모든 layer에서 그 die를 건너뛰어 불량 유출·수율 손실로 이어짐 (6.2)

| 기능 | 하는 일 |
|---|---|
| **Map Merge** | layer 순서대로 스캔한 맵의 reject die를 누적해 다음 layer 스캔 때 장비에 넣을 맵을 만듦 → 이미 reject된 die를 다시 스캔하지 않아 **생산성 향상** |
| **Map 변환** | KLA `.001`(defect가 나온 die 좌표 목록) → **Camtek 양식 맵 TXT**. 첫 layer를 KLA로 스캔하면 맵이 없어서 꼭 필요 |
| **스캔 안 함(skip)** | device마다 layer 목록을 정해 두고, 스캔하지 않은 layer는 체크박스로 건너뛰고 다음 layer로 merge (4.2) |
| 맵 이미지 | 모든 맵을 사진으로 그려 layer 순서대로 보여 줌. 클릭하면 원본 크기, 버튼으로 원본 텍스트 |
| **layer별 수율** | 이 layer 수율과 누적 수율 (4.4) |
| 안전장치 | 업로드 전 검사(A), 늘 처음부터 다시 계산(B), 업로드 이력·백업(C) (6장) |
| 업로드 | 결과 맵을 지정한 네트워크 폴더 **1곳**에 저장 (환경 시험으로 동작 확인) |

- 용어: **맵 파일** = Camtek 양식 맵 TXT. 고객사로 나가는 가장 범용적인 형식이고, 이 계획서의 "맵"은 모두 이것. KLA는 맵이 없는 특수한 경우
- **Layer** = 스캔 단계. device마다 개수·이름·순서가 다름 (예: TB500 = RDL4 → PI4 → RDL3 → PI3 → RDL2 → PI2 → RDL1)
- **Reject die** = 양품 코드(`BCEQU`, 보통 `000`)도 외곽(`___`)도 아닌 die
- 보류: 생산성 효과 표시(건너뛴 die 수·절감 시간). Batch Report가 필요해 복잡해짐 ([11장](#11-보류결정-기록))

## 1. 제조용 단순화

### 1.1 제조 화면은 3단계

```
① Lot 고르기   Lot 번호를 입력해 찾기, 또는 탐색기에서 Lot 폴더를 끌어다 놓기
                 → Lot 안의 layer 폴더를 읽어 layer 칸에 자동 배정
                 안내 문구: "리뷰(판정) 완료된 맵 파일을 사용하세요"
② 확인         스캔하지 않은 layer는 [스캔 안 함] 체크
                 wafer마다 초록(업로드 가능) / 노랑(확인 필요) / 빨강(업로드 안 됨 + 이유 한 줄)
                 맵 이미지·수율을 보고, 노랑은 확인 체크
③ 업로드       [업로드] 한 번. 결과·백업·기록은 프로그램이 알아서
```

- 버튼 이름 = 하는 일. 안내는 한 줄. 메시지는 **무엇이 문제 + 무엇을 하라**를 한 줄로
  (예: `PI4 폴더가 없습니다. 스캔하지 않은 layer면 [스캔 안 함]을 체크하세요.`)
- 배포물: HTML 파일 1개 + 그림 위주 A4 1장 사용 안내

### 1.2 경로 걱정 줄이기

경로는 **2곳뿐**이고 둘 다 고정: 리뷰 맵 공유 폴더(읽기), 업로드 폴더(쓰기, 1곳).

| 경로 | 방법 | 제조가 할 일 |
|---|---|---|
| 리뷰 맵 공유 폴더 | PC마다 처음 한 번 연결해 두면 **Lot 번호로 찾기** (폴더 이름만 봄) | 처음 한 번 연결, 그 뒤엔 Lot 번호 입력 |
| (대신) Lot 폴더 | 탐색기에서 **끌어다 놓기** | 경로 입력 없음 |
| 업로드 폴더 (1곳) | PC마다 처음 한 번 연결, 그 뒤로 기억 | 처음 한 번만 |
| 설정 (device·layer·코드 표 등) | 관리자가 정해 **HTML 파일 안에 넣어 배포** (7장) | 없음 |

- 브라우저 보안 규칙상 **폴더 연결은 PC마다 처음 한 번은 사람이 폴더를 직접 골라야 함** (피할 수 없음).
  그래서 처음 화면에 연결 카드 2개: 경로를 크게 보여 주고 [경로 복사] → 폴더 선택 창 주소 칸에 붙여넣기 → [폴더 선택]
- 연결할 때 프로그램이 **맞는 폴더인지 확인**: 폴더 이름이 설정과 같은지 보고, 다르면 연결하지 않음
  (업로드 폴더는 더 확실하게 관리자가 확인용 파일 1개를 두고 그 파일이 있는지 확인. 10장 질문)
- 배포할 때 관리자가 PC마다 연결까지 해 두면 제조는 이 단계도 없음
- 연결된 폴더는 화면 위쪽에 늘 표시 (`리뷰 맵: \\서버\...\REVIEW ✓ · 업로드: \\서버\...\MAP_IN ✓`).
  Edge를 다시 열면 [허용]을 한 번 눌러야 할 수 있음

### 1.3 리뷰 완료 맵 안내 (E)

- Lot 고르기 단계에 고정 문구: **"리뷰(판정) 완료된 맵 파일을 사용하세요. 리뷰 전 맵을 쓰면 false call die도 이후 layer에서 계속 건너뜁니다."**
- 리뷰 맵 공유 폴더에서 읽는 것이 기본이라 대부분 자연히 리뷰 완료 맵을 쓰게 됨

## 2. 폴더 구조

### 2.1 입력: 리뷰 맵 공유 폴더 (사용자 설명, 정확한 경로·이름은 나중에 받기로 함)

```
{리뷰 맵 공유 폴더}\{Lot}\{Layer}\
    Camtek layer: 맵 TXT (wafer마다) + slot 하위 폴더들
    KLA layer:    slot 폴더마다 .001
```

- **Camtek·KLA 구분 없이 Lot별로 모여 있고, Lot 안에 layer 폴더**가 있음 → Lot 폴더 하나만 고르면 모든 layer가 들어옴
- 장비 원본 폴더와 구조가 다를 수 있음. 아래 2.2는 파일·폴더 이름 규칙을 알아보는 참고용

### 2.2 참고: 장비 원본 폴더 (Para 저장소 조사)

| 장비 | 구조 | 출처 |
|---|---|---|
| Camtek | `{루트}\{AOI-호기}\Scanresult\{2D@레시피_디바이스}\{공정번호}\{S/M}\{웨이퍼번호}\`<br>예) `X:\AOI-6\Scanresult\2D@R2-1M3_0855360PD-0A\6321\HPG\CX05129990C4\` | `docs/commonality_조사_설계.md` |
| KLA | `{장비}\{YYYY-MM-DD}\{Lot}\{YYYY-MM-DD-HH-MM}_{슬롯}\` 안에 `*.jpg` · `{Recipe}_{Lot}_{Wafer}.001` · `{Recipe}_{Lot}_{Wafer}.pass`<br>예) `J:\2.K2\2025-05-21\RINT63@6324\2025-05-21-09-08_16` (슬롯 16) | `param_manager/desktop_kla.py` |

- KLA slot 폴더 이름에 **스캔 시각과 슬롯 번호**가 있음 → 같은 슬롯 폴더가 2개 이상이면 재스캔 (6.3)
- 레시피 이름에 layer·device가 들어 있음 (예: `R_RDL1_X_0856268PD-0A`, `2D@R3-S6WH11001-00001_0851974PD-0C`)

### 2.3 자동 인식

| 알아낼 것 | 방법 |
|---|---|
| KLA인지 Camtek인지 | layer 폴더 안에 `.001`이 있으면 KLA, 맵 TXT가 있으면 Camtek → **설정에 장비 종류를 적을 필요 없음** |
| layer | layer 폴더 이름 ↔ device 설정의 layer 이름(별칭 포함). 맞는 것이 없으면 노랑 + 제조가 ▼로 고름 |
| device | 맵 헤더 `DEVICE`·레시피 이름 ↔ device 설정. 못 찾으면 제조가 ▼로 고름 (마지막 선택 기억) |
| Lot | Lot 폴더 이름, 맵 헤더 `LOT`, `.001` 파일 이름 |

### 2.4 layer끼리 wafer 짝 맞추기: Wafer ID 기준

1. Camtek: 맵 헤더 `WAFER`
2. KLA: `.001` 안의 Wafer ID (KLA 결과 파일에는 보통 Wafer ID·Slot 항목이 있지만 **실제 파일로 확인 필요**)
3. KLA에 Wafer ID가 없으면: 같은 Lot의 Camtek 맵 헤더에 `SLOT`이 있을 때 **슬롯 ↔ Wafer ID 표**를 만들어 KLA 슬롯 번호(slot 폴더 이름)에 적용
4. 그것도 안 되면 슬롯 번호로만 짝 → 노랑 (`RDL3(KLA)는 슬롯 번호로 맞췄습니다. 확인하세요.`)

- 같은 Wafer ID가 두 번 나오거나 짝이 없는 wafer는 6.2 검사로 표시
- 참고: Para는 Wafer ID `SF14G25-A0`의 앞 5자를 Lot ID, `G25`를 슬롯 25로 읽음 (`param_manager/lotmodel.py`)

## 3. 맵 파일 형식과 이미지 (Para `version_wafermap` 조사)

Para 저장소의 최신 브랜치 `version_wafermap`(Wafer Map 변환 v1.0.0)을 참고 (`param_manager/wafermap.py`, `frontend/src/WaferMap.tsx`).

### 3.1 맵 TXT 형식 (SINF 계열)

```
WAFER:W01
DEVICE:DEV-A
LOT:LOT01
ROWCT:8
COLCT:8
RowData:___ ___ 000 000 000 000 ___ ___
RowData:___ 000 000 003 000 000 000 ___
... (ROWCT 줄)
```

- 헤더 `키:값`: `DEVICE` `LOT` `WAFER` `SLOT` `FNLOC`(Notch 각도) `ROWCT`(행 수) `COLCT`(열 수) `BCEQU`(양품 코드) `REFPX` `REFPY`(기준 die) `XDIES` `YDIES`(die 크기) 등
- `RowData:` 한 줄 = 맵 한 행, 3글자 코드 `COLCT`개. 첫 줄이 맵의 위쪽, Notch는 6시
- 검사: `ROWCT`·`COLCT` 필수, RowData 줄 수 = `ROWCT`, 줄마다 코드 수 = `COLCT`
- 인코딩 UTF-8(BOM 있음/없음)·CP949, 줄바꿈 CRLF/LF 혼재 → 원본 바이트 보존

| 코드 | 의미 | 색 |
|---|---|---|
| `___` | 웨이퍼 외곽 (die 없음) | 흰색 |
| `000` | 양품 | 연두 `#DDF3DF` |
| `003` | Metal Residue 금속 잔류물 | 빨강 `#D62728` |
| `007` | Irregular Bump 범프 불량 | 주황 `#D08C00` |
| `014` | RDL Defect | 선홍 `#E53935` |
| `022` | Scratch | 보라 `#7B1FA2` |
| `031` | Foreign Material 이물 | 파랑 `#1565C0` |
| `090` | Customer Map Reject Die 고객 맵 Reject | 회색 `#666666` |
| 그 외 | 미정의 Bin | 살구 `#F4B183` |

### 3.2 맵 이미지

- 흰 바탕, die 1개 = 정사각형 칸 (칸 크기 = `1100 ÷ max(행, 열)`, 4~22 px), 연한 격자선
- 축 눈금 10칸마다 (열: 왼→오, 행: 아래→위, 0부터), 제목 `{WAFER} … | Notch 6 o'clock`, 아래 가운데 Notch 삼각형
- 오른쪽 범례: 색 · `003 Metal Residue` · 개수 (Para는 코드용·의미용 2장 → **1장으로 합침**)
- 이미지 위쪽에 layer 이름·수율 표시

### 3.3 Para에서 바꾸는 것

- Excel 편집 없음 (보기·합치기·변환만), Python 대신 HTML 안의 JavaScript
- 원본 텍스트·이미지는 **화면 안 창**으로 띄움 (HTML은 메모장 같은 외부 프로그램을 실행할 수 없음)
- PNG는 화면에서 그리고, 파일 저장은 원할 때만

## 4. 기능 1: Map Merge

### 4.1 흐름 (TB500 예)

```
RDL4 ─► 누적 ① ─업로드→ PI4 스캔 (① 의 reject 건너뜀)
PI4  ─► 누적 ② = ① + PI4 새 reject ─업로드→ RDL3 스캔
RDL3 ─► 누적 ③ = ② + RDL3 새 reject ─업로드→ PI3 스캔
PI3  [스캔 안 함] ─► 누적 ③ 그대로 ─업로드→ RDL2 스캔
…
(어느 layer든 KLA면 .001 ─Map 변환─► 맵을 먼저 만든 뒤 합침. 첫 layer가 KLA여도 같음)
```

- **누적 맵은 늘 Camtek 양식.** KLA 쪽으로 보내는 맵은 만들지 않음
- 업로드하는 맵 = **다음에 스캔할 layer용** (마지막으로 합친 layer 다음의, [스캔 안 함]이 아닌 첫 layer). 화면에 `다음 스캔: RDL2 용 누적 맵` 표시

### 4.2 layer 설정과 [스캔 안 함]

- 관리자가 device마다 **layer 목록을 스캔 순서대로** 등록 (예: TB500 = RDL4, PI4, RDL3, PI3, RDL2, PI2, RDL1). 늘 건너뛰는 layer는 기본값으로 [스캔 안 함] 체크 가능
- 제조 화면의 layer 줄마다 **[스캔 안 함] 체크박스.** 체크하면 그 layer는 맵 없이 지나가고 누적 맵이 그대로 다음 layer로 감

| Lot 안에 이 layer 폴더 | [스캔 안 함] | 처리 |
|---|---|---|
| 있음 | 안 함 | 합침 |
| 있음 | 체크 | 노랑: `맵이 있는데 스캔 안 함으로 표시됨` → 이 layer 빼고 합침 |
| 없음 (뒤 layer 폴더는 있음) | 안 함 | 빨강: `PI4 폴더가 없습니다. 스캔하지 않은 layer면 [스캔 안 함]을 체크하세요.` |
| 없음 | 체크 | 건너뜀 (정상) |
| 없음 (뒤 layer 폴더도 없음) | - | 아직 스캔 전 (정상, 회색) |

- [스캔 안 함]으로 건너뛴 layer도 업로드 기록에 남김

### 4.3 Die 하나를 합치는 규칙

| 지금까지 누적 | 이번 layer | 결과 | 표시 |
|---|---|---|---|
| `___` | `___` | `___` | |
| `___` | 그 외 (또는 반대) | 업로드 안 됨 (빨강) | 웨이퍼 외곽이 다름 |
| 양품 | 양품 | 양품 | |
| 양품 | reject `X` | **`X`** | 이번 layer **새 reject** |
| reject `A` | 무엇이든 (`090` 등) | **`A`** | 먼저 걸린 layer의 코드 유지 |
| reject `A` | 양품 | `A` | 노랑: 건너뛰었어야 할 die가 양품으로 나옴 (장비에 누적 맵이 안 들어갔을 수 있음) |

- 양품 코드는 헤더 `BCEQU`, 없으면 `000`. die마다 **처음 reject된 layer**를 기억해 이미지·마우스 정보에 표시

### 4.4 layer별 수율

| 값 | 계산 |
|---|---|
| 전체 die | `___`가 아닌 칸 수 |
| 이 layer 검사 die | 전체 die − 이전 layer까지 누적 reject (건너뛴 die 제외) |
| 이 layer 새 reject | 4.3에서 이번 layer에 새로 reject된 die |
| **이 layer 수율** | (검사 die − 새 reject) ÷ 검사 die |
| **누적 수율** | (전체 die − 누적 reject) ÷ 전체 die |

- layer 줄마다 표시 ([스캔 안 함] layer는 `-`). Lot 화면에 wafer × layer 수율 표, [표 복사]로 Excel에 붙여넣기

### 4.5 화면

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ [Map Merge] [Map 변환]      리뷰 맵: \\...\REVIEW ✓  업로드: \\...\MAP_IN ✓  [관리자] │
│ Lot [RINT63      ][찾기]  또는 Lot 폴더를 여기에 끌어다 놓기    Device [TB500 ▼]     │
│ ※ 리뷰(판정) 완료된 맵 파일을 사용하세요                                            │
├──────────────────────────────────────────────────────────────────────────────┤
│ ① RDL4  Camtek  wafer 25 ✓            □ 스캔 안 함                              │
│ ② PI4   KLA     wafer 25 (.001→맵) ✓  □ 스캔 안 함                              │
│ ③ RDL3  Camtek  wafer 25 ✓            □ 스캔 안 함                              │
│ ④ PI3   폴더 없음                       ☑ 스캔 안 함                              │
│ ⑤ RDL2  아직 스캔 전   ◄ 다음 스캔: RDL2 용 누적 맵                                 │
│ ⑥ PI2 · ⑦ RDL1  아직 스캔 전                                                    │
├──────────────────────────────────────────────────────────────────────────────┤
│ Wafer [01 ●][02 ●][03 ▲][04 ●] …   ● 업로드 가능  ▲ 확인 필요  ■ 업로드 안 됨         │
│ ── Wafer 03 ───────────────────────────────────────────────────────────────── │
│ ① RDL4  [맵 이미지] [누적 이미지]  새 reject 120 · 이 layer 98.1% · 누적 98.1%       │
│         [원본 텍스트] [이미지 크게]                                               │
│ ② PI4   [맵 이미지] [누적 이미지]  새 reject 30 · 이 layer 99.5% · 누적 97.6%        │
│         ▲ 건너뛰었어야 할 die 2개가 양품으로 나옴  [확인함 □]                          │

├──────────────────────────────────────────────────────────────────────────────┤
```

- layer는 **스캔 순서대로 위에서 아래로**, wafer마다 이번 layer 맵과 그 시점의 누적 맵을 나란히
- **이미지 클릭** → 전체 화면 뷰어: 원본 크기, 휠 확대·끌어서 이동, ◀ ▶로 다른 layer, Esc 닫기, die 위 마우스 → 행·열·코드·처음 reject된 layer
- **[원본 텍스트]** → 화면 안 창에 원문 그대로 (줄 번호, 고정폭). `.001`도 원문 그대로
- 보기 전환: Bin 코드 색 / 이번 layer 새 reject만 강조

### 4.6 결과 파일

- 누적 맵 = **새 파일.** 첫 layer 맵(첫 layer가 KLA면 기준 맵)의 헤더·인코딩·BOM·줄바꿈·끝 빈 줄 그대로, **RowData 코드만 바뀜**
- 파일 이름 규칙은 경로와 함께 받기로 함

## 5. 기능 2: Map 변환 (KLA `.001` → Camtek 양식 맵)

- 쓰임: ① 첫 layer를 KLA로 스캔하면 맵이 없음 → 변환해야 다음 layer에 넣을 수 있음 ② Map Merge 안의 KLA layer (자동) ③ 단독 변환 (Map 변환 탭)
- `.001`에는 defect가 나온 die 좌표만 있어 맵 크기·외곽(`___`)·헤더가 없음 → device마다 **기준 맵**(같은 device의 Camtek 맵 1장)을 관리자가 등록

변환 순서:
1. `.001`에서 Lot·Wafer ID(있으면)·슬롯·레시피·defect die 좌표를 읽음
2. 기준 맵을 복사해 모든 die를 양품으로 시작 (`___`는 그대로)
3. KLA die 좌표 → 맵 행·열로 바꿔 reject 코드를 찍음
4. 헤더의 `LOT`·`WAFER` 등을 `.001` 값(또는 2.4로 찾은 Wafer ID)으로 바꿈

- **좌표 맞추기 (관리자, device마다 한 번)**: KLA 좌표와 Camtek 행·열은 원점·축 방향·Notch 방향이 다를 수 있음 → 이동(X·Y)·뒤집기·회전을 설정에 저장. 설정 화면에서 KLA defect 점을 기준 맵 이미지 위에 겹쳐 보며 맞춤. 좌표가 맵 밖·외곽에 떨어지면 빨강
- **Bin 코드**: KLA defect die에 쓸 코드는 사용자가 확인 중 (10장)
- 제조 화면: Lot 고르기 → KLA layer의 slot별 변환 맵 이미지 → 확인 → [업로드]. Map Merge와 같은 3단계

## 6. 안전장치 (A · B · C)

### 6.1 원본 보호 — 절대 규칙

1. 리뷰 맵 공유 폴더와 Lot 폴더는 브라우저에 **읽기 권한만** 요청해서 엶 → 프로그램이 원본에 쓸 권한 자체가 없음
2. 쓰기는 **업로드 폴더(와 그 안의 백업 폴더)에만**
3. 업로드 폴더가 리뷰 맵 폴더와 같거나 그 안에 있으면 **업로드 안 됨** (브라우저 기능으로 같은 폴더인지 확인)
4. 결과 파일이 원본 파일과 같은 파일이 되는 경우 **업로드 안 됨**
5. 프로그램에 원본을 지우거나 이름을 바꾸는 기능이 없음. 업로드 폴더의 기존 파일도 지우지 않고 백업 후 교체 (6.4)
6. 시험으로 보장: 모든 기능을 돌린 뒤 원본 파일의 SHA-256·파일 목록이 그대로인지 자동 시험 (8장)

### 6.2 A. 업로드 전 검사

| 결과 | 검사 |
|---|---|
| **빨강 (업로드 안 됨)** | 맵 읽기 오류 · layer끼리 맵 크기(`ROWCT`/`COLCT`)나 외곽(`___`) 다름 · layer끼리 `LOT` 다름 · Wafer ID 짝이 안 맞음(같은 ID 두 번 등) · 중간 layer 폴더가 없는데 [스캔 안 함] 체크 안 함 · KLA 좌표가 맵 밖 · 6.1의 3, 4번 |
| **노랑 (확인 체크 후 업로드)** | **reject 급증** (이 layer 새 reject 비율이 관리자 기준값보다 큼) · 건너뛰었어야 할 die가 양품으로 나옴 · 미정의 Bin 코드 · 슬롯 번호로만 wafer 짝을 맞춤 · 맵이 있는데 [스캔 안 함] 체크됨 · layer 폴더 이름이 설정과 안 맞아 ▼로 고름 · 일부 layer에만 있는 wafer |
| **초록** | 위에 해당 없음 |

- 업로드 직전 화면: wafer별 초록/노랑/빨강과 이유 한 줄, **이미 올라가 있는 맵과 비교** (예: `reject +30, 사라진 reject 0`)
- 업로드 후 다시 읽어 바이트 비교 (환경 시험과 같은 방식)

### 6.3 B. 늘 처음부터 다시 계산

- 누적 맵은 **매번 원본 layer 맵들만으로 처음부터 계산.** 이전에 만든 누적 맵을 고쳐 나가지 않음 → 같은 입력이면 언제나 같은 결과(바이트까지)
- 이미 올라가 있는 누적 맵은 비교용으로만 보고, 계산에 쓰지 않음
- 같은 layer·wafer의 결과가 여러 개면(재스캔) **가장 늦은 스캔**을 쓰고 화면에 `재스캔 2회 중 최신 사용` 표시

### 6.4 C. 업로드 이력·백업

- 업로드 폴더에 같은 이름 파일이 있으면 먼저 **`_KLA_Camtek_백업\{날짜_시각}\`으로 복사**한 뒤 새 파일로 교체
- 업로드할 때마다 같은 백업 폴더에 `기록.txt`: 시각 · Lot · wafer · 사용한 layer 파일(이름·스캔 시각) · [스캔 안 함] layer · 결과 파일 · 새 reject · 수율 · 확인한 노랑 항목
  (한 파일에 이어 쓰지 않고 업로드마다 따로 남겨 여러 PC가 동시에 올려도 섞이지 않음)
- [이력 보기]: 최근 업로드 목록, [이전 맵으로 되돌리기] (되돌릴 때도 지금 파일을 먼저 백업)

## 10. 확인이 필요한 것과 자료

### 10.1 정해진 것 (2026-10-16 답변)

- 입력은 리뷰 맵 공유 폴더: Camtek·KLA 구분 없이 `{Lot}\{Layer}\` (정확한 경로·구조는 나중에)

- wafer 짝은 Wafer ID 기준 (KLA에 Wafer ID가 있는지는 확인 예정)

## 11. 보류·결정 기록

- **보류: 생산성 효과 표시** (layer마다 건너뛴 die 수·절감 스캔 시간·Lot 요약). 스캔 시간은 Batch Report를 가져와야 해서 복잡해짐 → 제조용으로 간단하게 만드는 목적에 맞지 않아 보류
