## 0. 한눈에 보기

| 기능 | 하는 일 | 목적 |
|---|---|---|
| **Map Merge** | layer 순서대로 스캔한 맵들의 reject die를 누적해 하나의 맵으로 합침. 다음 layer 스캔 때 장비에 넣는 맵 | 이전 layer에서 이미 reject된 die를 다음 layer에서 다시 스캔하지 않음 → **생산성 향상** |
| **Map 변환** | KLA `.001`(defect가 나온 die 좌표 목록) → **Camtek 양식 맵 TXT** | KLA layer도 Merge에 넣고, 고객사에 나가는 표준 맵을 만들기 위해 |
| 공통: 맵 이미지 | 모든 맵 TXT를 사진으로 그려 layer 순서대로 보여 줌. 클릭하면 원본 크기, 버튼으로 원본 텍스트 | 사람이 한눈에 확인하고 프로그램 오류를 잡기 위해 |
| 공통: 업로드 | 결과 맵을 지정한 네트워크 경로에 저장 | 환경 시험으로 동작 확인 완료 |

용어:
- **맵 파일** = Camtek 양식 맵 TXT. 고객사로 나가는 가장 범용적인 형식이고, 이 계획서에서 "맵"은 모두 이것을 말한다. KLA는 맵이 없는 특수한 경우
- **Layer** = 스캔 단계 (예: PI2~PI4, RDL1~RDL4, 그 밖에 직접 입력). **device마다 개수·이름·순서가 다름**
- **Reject die** = 양품 코드(`BCEQU`, 보통 `000`)도 외곽(`___`)도 아닌 die

## 1. 참고 조사: Para `version_wafermap` (Wafer Map 변환 v1.0.0)

Para 저장소의 가장 최근 브랜치 `version_wafermap`(2026-10-16)은 Wafer Map TXT ⇄ Excel 변환 전용판이다.
그대로 쓰지는 않지만 맵 형식과 이미지 틀은 여기서 가져온다. (`param_manager/wafermap.py`, `frontend/src/WaferMap.tsx`)

### 1.1 맵 TXT 형식 (SINF 계열)

```
WAFER:W01
DEVICE:DEV-A
LOT:LOT01
ROWCT:8
COLCT:8
RowData:___ ___ 000 000 000 000 ___ ___
RowData:___ 000 000 003 000 000 000 ___
RowData:000 000 000 000 000 007 000 000
... (ROWCT 줄)
```

- **헤더** = `키:값` 줄. 자주 나오는 키: `DEVICE` `LOT` `WAFER` `FNLOC`(Flat/Notch 각도) `ROWCT`(행 수) `COLCT`(열 수)
  `BCEQU`(양품 코드) `REFPX` `REFPY`(기준 die 좌표) `DUTMS`(단위) `XDIES` `YDIES`(die 크기)
- **RowData** = 맵 한 행에 한 줄, 공백으로 나눈 3글자 코드 `COLCT`개. 첫 RowData 줄이 맵의 **위쪽**, Notch는 **6시**
- 검사: `ROWCT`·`COLCT` 필수, RowData 줄 수 = `ROWCT`, 모든 줄의 코드 수 = `COLCT`
- 인코딩 UTF-8(BOM 있음/없음)·CP949, 줄바꿈 CRLF/LF가 섞여 있음 → **원본 바이트 보존**이 원칙
  (Para는 줄마다 헤더/RowData 배치를 기억해 끝 빈 줄까지 그대로 되돌림)

Bin 코드 표 (Para 기본값):

| 코드 | 의미 | 한글 | 색 |
|---|---|---|---|
| `___` | Outside Wafer | 웨이퍼 외곽 (die 없음) | 흰색 `#FFFFFF` |
| `000` | Accept / Good | 양품 | 연두 `#DDF3DF` |
| `003` | Metal Residue | 금속 잔류물 | 빨강 `#D62728` |
| `007` | Irregular Bump | 범프 불량 | 주황 `#D08C00` |
| `014` | RDL Defect | RDL 불량 | 선홍 `#E53935` |
| `022` | Scratch | 스크래치 | 보라 `#7B1FA2` |
| `031` | Foreign Material | 이물 | 파랑 `#1565C0` |
| `090` | Customer Map Reject Die | 고객 맵 Reject Die | 회색 `#666666` |
| 그 외 | Unknown Bin | 미정의 | 살구 `#F4B183` |

### 1.2 맵 → 이미지 방식

- 맵 1개에서 2장: **Bin Code Map**(범례 `Bin 003 (개수)`) · **Bin Meaning Map**(범례 `Metal Residue (개수)`)
- 흰 바탕, die 1개 = 정사각형 칸. 칸 크기 = `1100 ÷ max(행, 열)`을 4~22 px로 제한 (100×100 맵 ≈ 11 px)
- 칸 사이 연한 격자선, 바깥 테두리, 축 눈금 10칸마다 (열: 왼→오 0부터, 행: **아래→위** 0부터)
- 제목 `{WAFER}  Bin Code Map | Notch 6 o'clock`, 맵 아래 가운데 Notch 삼각형, 오른쪽 범례(색·이름·개수)
- Para는 matplotlib 그림을 canvas로 옮겨 그렸고, PNG(`{원본}_BinCode_Map.png`)를 결과 폴더에 저장

### 1.3 가져올 것 / 바꿀 것

| 가져올 것 | 바꿀 것 |
|---|---|
| 파서 규칙과 검사, 원본 바이트 보존 원칙 | Excel 편집 기능은 없음 (보기·합치기·변환만) |
| Bin 코드 색·의미 표 (device별로 추가 가능하게) | Python 엔진 대신 HTML 안의 JavaScript |
| 그림 배치 (제목·축·Notch·범례·격자) | 이미지를 2장 대신 **1장** (범례에 `003 Metal Residue (12)`처럼 코드와 의미 함께) |
| 원본은 읽기만, 결과는 늘 새 파일 | PNG는 화면에서 그리고, 저장은 원할 때만 |
| | 원본 텍스트·이미지는 **화면 안 창**으로 띄움 (HTML은 메모장 같은 외부 프로그램을 실행할 수 없음) |

### 1.4 KLA 결과 폴더 (Para `param_manager/desktop_kla.py`)

```
{KLA 장비 폴더}\{YYYY-MM-DD}\{Lot}\{YYYY-MM-DD-HH-MM}_{슬롯}\
    *.jpg (Defect 이미지) · {Recipe}_{Lot}_{Wafer}.001 · {Recipe}_{Lot}_{Wafer}.pass
예) J:\2.K2\2025-05-21\RINT63@6324\2025-05-21-09-08_16
```

- 레시피 이름에 layer·device가 들어 있음 (Para 예: `R_RDL1_X_0856268PD-0A`, Camtek 예: `TB500_RDL4 - Multi`)
  → 파일 이름에서 **layer · Lot · Wafer를 자동으로 알아낼 수 있을 가능성**이 큼 (샘플로 확인)
- `.001`은 KLA의 결과 파일(KLARF 계열로 추정). 샘플을 받으면 형식 확정

## 2. 기능 1: Map Merge

### 2.1 흐름 (예: RDL4 → RDL3 → RDL2 순서로 스캔하는 device)

```
RDL4 스캔 ─► RDL4 맵 ─────────────────────► 누적 맵 ① (= RDL4 reject)
                                                   │ 장비에 넣음 → RDL3 스캔 때 ① 의 reject die는 건너뜀
RDL3 스캔 ─► RDL3 맵 (새 reject만 의미 있음) ─► 누적 맵 ② = ① + RDL3 새 reject
                                                   │ 장비에 넣음 → RDL2 스캔
RDL2 스캔 ─► RDL2 맵 ─────────────────────► 누적 맵 ③ = ② + RDL2 새 reject …
```

- layer 순서와 각 layer의 장비 종류(KLA/Camtek)는 **device 설정**에서 정함 (5.1)
- KLA layer는 먼저 `.001` → 맵 TXT 변환(3장)을 거친 뒤 같은 방법으로 합침

### 2.2 Die 하나를 합치는 규칙

| 누적 맵 (지금까지) | 이번 layer 맵 | 결과 | 표시 |
|---|---|---|---|
| `___` | `___` | `___` | |
| `___` | 그 외 / 그 반대 | **merge 중단** | 오류: 웨이퍼 외곽이 다름 (다른 device·맵 크기) |
| 양품 | 양품 | 양품 | |
| 양품 | reject `X` | **`X`** | 이번 layer의 **새 reject** |
| reject `A` | 무엇이든 (`090` 등) | **`A`** | 먼저 걸린 layer의 코드 유지 (제안) |
| reject `A` | 양품 | `A` | **경고**: 건너뛰었어야 할 die가 양품으로 나옴 → 장비에 누적 맵이 안 들어갔을 수 있음 |

- 양품 코드는 헤더 `BCEQU`를 따르고, 없으면 `000`
- die마다 **처음 reject된 layer**를 기억해 이미지와 마우스 정보에 보여 줌

### 2.3 프로그램 오류·작업 실수 검사

| 검사 | 걸리면 |
|---|---|
| `ROWCT`·`COLCT`, 외곽(`___`) 위치가 layer끼리 같은지 | 오류, merge 안 함 |
| `DEVICE`·`LOT`·`WAFER`가 같은지, `FNLOC`·`REFPX`·`REFPY`가 같은지 | 오류 또는 경고 (항목별로 정함) |
| 이전 reject die가 다음 layer에서 양품 | 경고 + 해당 die 강조 |
| 표에 없는 Bin 코드 | 경고 (살구색) |
| 설정된 layer가 빠졌거나 순서가 다름 | 경고 |
| KLA 변환 결과 좌표가 맵 밖이나 외곽에 떨어짐 | 오류 (3.3 좌표 설정 확인) |

### 2.4 화면 구성

```
┌──────────────────────────────────────────────────────────────────────────────────┐
│ [Map Merge] [Map 변환] [설정]          Device [0856268PD ▼]  Lot RINT63  Wafer [01 ▼] ◀ ▶ │
├──────────────────────────────────────────────────────────────────────────────────┤
│ 파일 넣기: 끌어 놓기 · [파일 열기] · [폴더 열기]  → 파일 이름으로 layer 자동 배정 (틀리면 ▼로 수정) │
├──────────────────────────────────────────────────────────────────────────────────┤
│ ① RDL4 · Camtek · TB500_RDL4_..._01.txt                                            │
│   [이번 layer 맵 이미지] [누적 결과 이미지]   reject 120 · 새로 120 · 누적 120 · 수율 98.1%  │
│   [원본 텍스트] [이미지 크게]                                                       │
│ ② RDL3 · KLA (.001 → TXT) · R_RDL3_..._01.001                                      │
│   [이번 layer 맵 이미지] [누적 결과 이미지]   reject 45 · 새로 30 · 누적 150 · ⚠ 경고 1   │
│ ③ …                                                                              │
├──────────────────────────────────────────────────────────────────────────────────┤
│ 최종 누적 맵 (큰 이미지) · 검사 결과 · [누적 맵 저장] [업로드 → 지정 경로] [PNG 저장]          │
└──────────────────────────────────────────────────────────────────────────────────┘
```

- **layer 순서대로 위에서 아래로** 나열. 각 줄에 이번 layer 맵과 그 시점의 누적 결과를 나란히
- **이미지 클릭** → 전체 화면 뷰어: 원본 크기 이미지, 휠 확대·끌어서 이동, ◀ ▶ / ←→로 다른 layer, Esc 닫기,
  die 위에 마우스 → 행·열·코드·의미·처음 reject된 layer
- **[원본 텍스트]** → 화면 안 창에 원문 그대로 (줄 번호, 고정폭 글꼴). 이미지에서 die를 클릭하면 그 RowData 줄·칸 강조
- 보기 전환: **Bin 코드 색** / **어느 layer에서 reject됐는지 색** / **이번 layer 새 reject만 강조**
- Lot 단위로 넣으면 wafer별로 처리하고, 목록에 오류·경고가 있는 wafer를 표시

### 2.5 결과 파일

- 원본 맵은 절대 고치지 않음. 누적 맵은 **새 파일**
- 첫 layer 맵의 헤더·인코딩·BOM·줄바꿈·끝 빈 줄을 그대로 두고 **RowData 코드만 바뀜**
- 파일 이름과 저장 위치는 확인 필요 (9장)

## 3. 기능 2: Map 변환 (KLA `.001` → Camtek 양식 맵)

### 3.1 입력과 부족한 정보

- `.001` = defect가 나온 **die 좌표 목록**만 있음 → 맵 크기, 외곽(`___`) 모양, 헤더 값이 없음
- 그래서 device마다 **기준 맵**이 필요: 같은 device의 Camtek 맵 1장을 기준으로 등록 (맵 크기·외곽·헤더를 여기서 가져옴)

### 3.2 변환 순서

1. `.001`에서 Lot·Wafer·레시피·defect die 좌표를 읽음
2. 기준 맵을 복사하고 모든 die를 양품으로 시작 (`___`는 그대로)
3. KLA die 좌표 → 맵 행·열로 바꿔 reject 코드를 찍음 (3.3)
4. 헤더의 `LOT`·`WAFER` 등을 `.001` 값으로 바꿈
5. 변환된 맵 이미지와 텍스트를 나란히 보여 주고 저장·업로드. Merge에서는 자동으로 이 과정을 거침

### 3.3 좌표 맞추기 (device마다 한 번)

- KLA die 좌표와 Camtek 행·열은 원점·축 방향·Notch 방향이 다를 수 있음 → device 설정에 **이동(X·Y)·뒤집기·회전** 저장
- 설정 화면에서 KLA defect 점을 기준 맵 이미지 위에 겹쳐 보여 주고, 맞을 때까지 조정 → 저장
- 같은 wafer를 양쪽 장비로 찍은 자료가 있으면 자동으로 맞춰 볼 수 있음
- 좌표가 맵 밖이나 외곽에 떨어지면 오류

### 3.4 Bin 코드

- KLA defect die에 어떤 코드를 쓸지: 코드 하나로 통일 또는 KLA 분류 → Camtek 코드 대응표 (9장 질문)

## 4. 화면 공통

- 상단 탭: **Map Merge** · **Map 변환** · **설정**
- 파일 넣기 3가지: 끌어 놓기(폴더면 하위까지), 파일 열기 창, 폴더 열기 창 (환경 시험에서 확인)
- 맵 이미지 뷰어, 원본 텍스트 창은 두 기능이 같이 씀
- 모든 작업 기록(무엇을 읽고, 합치고, 어디에 저장했는지)을 화면 아래에 남기고 TXT로 저장 가능

- 같은 이름 파일이 있을 때 처리(묻기 / 백업 후 덮어쓰기 / 덮어쓰기)는 확인 후 결정

## 6. 기술 구조

- 결과물: `programs/KLA_Camtek_Converter/KLA_Camtek_Converter.html` 1개 (외부 파일·인터넷 없음)
- 안쪽은 **엔진**(파싱·검사·merge·KLA 변환·바이트 보존 쓰기·그리기, 화면과 분리된 순수 함수)과 **화면**으로 나눔
- 인코딩: UTF-8·CP949 읽기. 쓸 때는 **헤더 줄의 원본 바이트를 그대로 복사**하고 RowData 줄(ASCII)만 새로 씀
  → 브라우저에 CP949 쓰기 기능이 없어도 한글 헤더가 깨지지 않음
- 이미지: canvas에 1.2의 배치로 그림. 화면용은 바로 그리고, PNG 저장은 요청할 때만
- 성능: 환경 시험에서 1000×1000 맵(die 약 78만 개)을 초당 약 50번 다시 그림
- 시험: Python unittest + Playwright(이미 Release 워크플로에 있음)로 HTML을 열어 엔진 함수를 직접 호출
  - 샘플 맵 파싱·검사, 바이트 단위 왕복 동일, 2.2 규칙표 전부, `.001` 변환, 이미지 그리기
- 배포: HTML 파일 1개를 네트워크 공유 폴더에 두고 바로가기만 나눠 줌. 버전은 화면 제목에 표시

## 7. 추가 기능 제안 (골라 주세요)

목적(다음 layer 스캔을 줄여 생산성 향상)이 **잘못된 맵 때문에 오히려 손해가 되지 않게 지키는 기능**과, **효과를 숫자로 보여 주는 기능**.

**꼭 넣기를 권하는 것**

| # | 기능 | 왜 필요한가 |
|---|---|---|
| A | **업로드 전 안전 검사**: wafer 일치(파일 이름·헤더 `LOT`/`WAFER`·슬롯), 2.3 검사, **reject 급증 경고**(이번 layer reject가 설정값보다 많으면 업로드 보류) | 다른 wafer의 맵이나 초점 불량 같은 비정상 스캔 맵이 한 번 누적되면, 이후 모든 layer에서 그 die를 건너뛰어 **불량 유출·수율 손실**로 이어짐 |
| B | **누적 맵은 늘 layer 맵들로 처음부터 다시 계산.** 같은 layer를 다시 스캔하면 최신 파일로 바꿔 계산 | 누적 파일을 덧붙여 고쳐 나가면 재스캔·순서 실수 때 틀린 맵이 남음. 다시 계산하면 언제 돌려도 같은 결과 |
| C | **업로드 이력·백업**: 덮어쓰기 전 기존 파일을 보관 폴더에 시각을 붙여 남기고, 언제 어떤 맵을 어디에 올렸는지 기록 | 잘못 올렸을 때 바로 되돌리기, 문제가 생겼을 때 추적 |
| D | **생산성 효과 표시**: layer마다 건너뛴 die 수·비율, 절감 스캔 시간 추정, Lot 요약 CSV | 이 프로그램의 목적을 숫자로 보여 줌 (보고용) |

**필요하면 넣을 것**

| # | 기능 | 설명 |
|---|---|---|
| E | **리뷰 결과(GOOD 처리) 반영** | 리뷰에서 false call로 GOOD 처리한 die를 누적 맵에서 뺌. 빼지 않으면 양품 die가 이후 모든 layer에서 계속 건너뛰어짐. Camtek 맵이 리뷰 전/후 어느 쪽인지, AOI Photo Sorter의 GOOD 목록과 연결할 수 있는지 확인 필요 |
| F | 폴더 자동 감시 | 창을 켜 두면 새 layer 맵이 생길 때 자동으로 누적하고 검사 통과 시 업로드(또는 확인 후 업로드). 브라우저라 창이 열려 있을 때만 동작 |

## 9. 확인이 필요한 것과 필요한 자료

### 9.1 질문

**Map Merge**
1. device 1개를 예로 layer 목록과 **스캔 순서** (예: RDL4 → RDL3 → … 맞는지), layer마다 KLA/Camtek 중 어느 장비인지
2. 누적 맵을 넣고 스캔하면 장비가 **건너뛴 die를 결과 맵에 어떤 코드로** 쓰는지 (`090` Customer Map Reject Die?)
3. 여러 layer에서 reject된 die는 누적 맵에 **먼저 걸린 layer의 코드**를 남겨도 되는지
4. 장비가 읽는 **입력 맵의 경로·파일 이름**이 고정인지 (기존 파일을 덮어써야 하는지)
5. Camtek 맵 TXT가 생기는 위치(Scanresult 아래 경로 예)와 **파일 이름 규칙** → layer·Lot·Wafer 자동 인식용
6. 작업 단위: wafer 1장씩인지, Lot(25장) 일괄인지

**Map 변환**
7. `.001` 샘플과 같은 폴더의 `.pass` 파일이 무엇인지
8. KLA 좌표 ↔ Camtek 행·열 대응. **같은 wafer를 양쪽에서 찍은 `.001`과 Camtek 맵**이 있으면 가장 좋음
9. KLA defect die에 쓸 Bin 코드 (코드 하나로 통일 / 분류별 대응표)
10. KLA 장비도 누적 맵을 받아야 하는지 (Camtek → KLA 방향 변환이 필요한지)
11. 고객사로 나가는 맵에 꼭 들어가야 하는 헤더 항목

**기타**
12. 본 프로그램을 이 저장소(`related-AOI-program`)에 둘지, 새로 만든 `KLA-CAMTEK-CONVERTER` 저장소에 둘지

### 9.2 필요한 자료

Lot·device 이름 같은 민감한 값은 바꿔도 됩니다. 단 **좌표·코드·헤더 형식·파일 이름 형식은 그대로** 주세요.

1. **같은 Lot·Wafer의 layer별 Camtek 맵 TXT 전부** (스캔 순서대로, 2~3장이라도)
2. **누적 맵을 장비에 넣고 스캔한 뒤 나온 결과 맵** 1개 (건너뛴 die가 어떤 코드로 나오는지 확인)
3. **KLA `.001` + `.pass`** 샘플. 가능하면 같은 wafer의 Camtek 맵도 함께
4. device 1~2개의 **layer 목록·스캔 순서·layer별 장비**
5. **경로 예**: Camtek 맵이 생기는 경로, KLA `.001` 경로, 장비가 입력 맵을 읽는 경로와 파일 이름
6. **Bin 코드 전체 목록**(device별 추가 코드), 고객사 맵 사양(필수 헤더·허용 코드)이 있으면
7. **지금 방식**: merge를 지금은 어떻게 하는지(수작업·엑셀 등), wafer당 die 수와 layer 스캔 시간 (D 효과 계산용)
