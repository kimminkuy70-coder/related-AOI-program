## AOI Photo Sorter v4 — 추가 GOOD 검토 모드

리뷰를 마친 뒤 REJECT로 남은 사진 중에서 GOOD을 더 고를 수 있습니다. 설치와 기본 사용법은 v3와 같습니다. `AOI_Photo_Sorter_v4.zip`을 새 폴더에 풀고 `AOI_Photo_Sorter_v4.vbs`를 실행하세요. 진행 중이던 작업(이어하기)과 저장 위치 설정은 그대로 이어집니다.

### 바뀐 점
- **추가 GOOD 검토 시작**: 시작 화면에서 사진 폴더와 결과 저장 위치를 지정했을 때 그 위치에 이전 결과(`<폴더명>_GOOD.txt` / `_REJECT.txt`)가 있으면 `이전 결과: GOOD n / REJECT m (저장 시각)` 안내와 [추가 GOOD 검토 시작] 버튼이 나타납니다. 다른 PC에서 만든 결과 파일도 사용할 수 있습니다. 기존 [시작]은 그대로입니다.
- **REJECT로 남은 사진만 검토**
  - 이미 GOOD인 사진은 건너뜁니다(네트워크에서도 읽지 않음). 키 조작은 일반 모드와 같습니다.
  - 위쪽에 「추가 검토」 표시와 `REJECT N장 중 k번째`, `추가 GOOD n`이 표시됩니다.
  - 이전 결과를 저장한 뒤 폴더에 새로 생긴 사진도 검토 대상에 들어가고, 아래쪽에 「신규」가 붙습니다.
  - 결과 파일에는 있지만 폴더에서 사라진 사진은 제외하고 개수만 알려 줍니다.
  - 기존 GOOD은 이 모드에서 해제할 수 없습니다(추가만 가능).
- **확인 화면**: 이번에 추가한 GOOD만 썸네일로 보여 주고(클릭·Space로 해제 가능), 기존 GOOD은 개수만 표시합니다.
- **저장**
  - `<폴더명>_GOOD.txt`: 기존 GOOD + 이번에 추가한 GOOD, `<폴더명>_REJECT.txt`: 그래도 남은 REJECT. 형식은 그대로입니다(파일명 1줄, 폴더 정렬 순서, UTF-8, CRLF).
  - 갱신 전 파일은 `<폴더명>_GOOD_이전_날짜_시각.txt` / `<폴더명>_REJECT_이전_날짜_시각.txt`로 백업됩니다.
  - 이번에 추가한 GOOD만 담은 `<폴더명>_GOOD_추가_날짜_시각.txt`도 만듭니다.
  - 검토를 시작한 뒤 결과 파일이 바뀌었으면(다른 PC에서 저장 등) 저장 전에 확인을 받습니다.
- **진행 저장 / 이어하기**: 추가 검토는 일반 작업과 별도로 자동 저장되어 일반 작업 기록을 덮어쓰지 않습니다. 저장하지 않고 꺼졌으면 「추가 GOOD 검토 이어하기」로 계속하거나 [처음부터]로 새로 시작할 수 있습니다. 저장한 뒤 다시 하면 그 시점의 최신 결과 파일 기준으로 시작합니다.
- 시작 화면의 버전 표시를 v4로 고쳤습니다(이전에는 v1로 남아 있었음).

### 검증
- 측정 환경: Linux, Chromium headless(WebView2와 같은 엔진).
- 단위 테스트: 이전 결과 읽기(BOM, ANSI 저장 파일 포함), 신규/사라진 사진 처리, 병합 저장·백업·추가 목록, 결과 파일 도중 변경 감지, 세션 분리, 서버 흐름(시작·이어하기·저장·재저장).
- E2E: 시작 화면 → 추가 GOOD 검토 → 확인 화면 → 저장까지 실제 화면으로 확인.
- 기존 테스트(연타·1만 장·끊김/복구/F5 포함)도 모두 통과했습니다.
- **Windows 실기와 실제 공유 폴더에서는 아직 확인하지 않았습니다.** 문제가 생기면 `%LOCALAPPDATA%\AOI_Tools\logs\AOI_Photo_Sorter.log`를 함께 전달해 주세요.
