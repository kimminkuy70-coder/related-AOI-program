## AOI Photo Sorter v9 — v8 .exe가 실행 중 "트로이 목마"로 종료되던 문제 대응

### 원인
- v8 `.exe`가 실행 중(사진 폴더 [찾아보기]로 네트워크 폴더를 오가는 중 등)에 갑자기 꺼진 것은 **Windows Defender가 그 .exe 파일을 `트로이 목마`(예: `Trojan:Win32/Wacatac...!ml`)로 오탐해 실행 중인 프로그램을 강제로 종료**했기 때문입니다. 프로그램 코드가 죽은 것이 아닙니다.
  - `!ml` 판정은 Defender 클라우드 머신러닝이 **파일(해시)마다** 확률로 내립니다. 서명 없는 PyInstaller one-file .exe는 버전마다 해시가 새로 바뀌어 평판이 0부터 시작하므로, 같은 방식으로 만든 v7은 통과하고 v8은 걸리는 일이 생깁니다.
  - Defender는 처음 보는 .exe를 일단 실행시킨 뒤 클라우드 분석 결과가 오면 그때 프로세스를 끝냅니다. 그래서 시작 직후 하는 작업(폴더 고르기) 도중에 꺼진 것처럼 보입니다.
  - 한 번 판정된 파일은 **다시 받아도 계속 같은 방식으로 막힙니다**("자꾸 종료").
- v7 → v8에서 바뀐 것은 폴더 끝에서 Enter로 다음 폴더, 전체 결과 보기, 사진 경로 패널(선택·복사·파일 끌어 놓기)뿐이고, **폴더 고르기 창과 .exe 빌드 방식은 v7과 완전히 같습니다**(같은 `tools/build_exe.py`, 같은 PyInstaller 설정). v8 기능 자체가 종료 원인이 아닙니다.

### 바뀐 점
- 버전 v8 → v9로 다시 빌드한 **새 .exe**(다른 해시)입니다. v8 .exe에 내려진 차단 판정과 무관하게 받을 수 있습니다. 기능·사용법은 v8과 같습니다.
- README에 Defender가 .exe를 막거나 실행 중 종료시킬 때의 대처(ZIP 버전 사용)를 적었습니다.

### 그래도 .exe가 막히거나 꺼지면
- **ZIP 버전(`AOI_Photo_Sorter_v9.zip`의 `.vbs`)으로 실행하세요.** python.org의 서명된 Python으로 실행되어 이 오탐 대상이 아닙니다(설정·진행 상황은 .exe와 같은 곳에 저장되어 이어집니다).
- 회사 PC라면 IT에 Defender 허용 등록(파일 해시 또는 폴더 예외)을 요청하거나, https://www.microsoft.com/wdsi/filesubmission 에 오탐 신고(Software developer → Incorrectly detected)를 하면 보통 며칠 안에 풀립니다.
- 근본 해결은 코드 서명 인증서로 .exe를 서명하는 것입니다(인증서가 필요해 자동 빌드에는 넣지 못했습니다).

### 검증
- 단위·화면 시험은 v8과 같이 통과했습니다. Windows .exe 빌드와 자체 시험은 릴리스 워크플로(Windows)에서 통과한 것만 게시됩니다.
- Linux 환경이라 실제 PC에서의 Defender 판정은 확인할 수 없습니다. 새 해시가 통과할지는 받는 PC의 Defender 판정에 달려 있습니다.
