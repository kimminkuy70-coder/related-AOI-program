# AOI Photo Sorter (사진 O/X 분류기) — 개발 계획서 (검토용)

- 상태: **계획 검토 단계** (아직 코드 없음. 이 문서 승인 후 구현)
- 브랜치: `claude/cool-meitner-n7uz0l`
- 목적: 네트워크 폴더에 있는 사진(폴더당 최대 1만 장)을 한 장씩 보면서 키보드 O/X로 빠르게 분류하고, O 목록과 X 목록을 텍스트 파일 2개로 저장

| 진행 보호 | 1초마다 로컬에 자동 저장. 프로그램이 꺼져도 같은 폴더를 다시 열면 "이어하기" |
| 확인 단계 | O/X 썸네일 그리드(클릭으로 O↔X 전환) + "X만 빠르게 재확인" 모드 |
| 결과 | `<폴더명>_O.txt`, `<폴더명>_X.txt` — 한 줄에 파일 이름 1개 |
| 목표 성능 | 키 입력 → 다음 사진 1프레임(≈16 ms) 이내, 초당 20회 연타에서도 누락·중복 0건 |

## 1. 요구사항 정리

1. 폴더 안의 사진을 O/X 두 그룹으로 분류한다.
2. 폴더당 최대 1만 장, **네트워크 폴더**(사내 공유 폴더, `\\서버\공유\...`)라 사진 하나를 여는 데 시간이 걸린다.
3. 흐름: 폴더 지정 → 사진 로딩 → 한 장씩 보며 키보드 O/X → 분류 결과 한 번 확인 → O 목록, X 목록을 **사진 이름만** 텍스트 파일 2개로 저장
4. 속도가 최우선. 빠른 로딩, 그리고 키보드를 빠르게 연타해도 문제없이 동작해야 한다.

### 1-1. 결정이 필요한 항목 (제안 기본값으로 진행해도 되는지 확인 부탁드립니다)

| # | 항목 | 제안 기본값 | 대안 |
|---|---|---|---|
| Q1 | 분류 키 | **`O` 키 = O, `X` 키 = X** (양손 사용), 보조키 숫자 `1` = O, `2` = X | ←/→ 방향키, F/J 등 (설정에서 변경 가능하게 만들 예정) |
| Q2 | 대상 사진 형식 | `.jpg .jpeg .png .bmp` (+ `.tif .tiff`는 자동 변환해 표시) | 형식 추가/제외 |
| Q3 | 하위 폴더 | **선택한 폴더만** (하위 폴더 미포함) | 하위 폴더 포함 시 결과에 상대 경로 기록 |
| Q4 | 결과 파일 내용 | 파일 이름 **확장자 포함**(`IMG_0001.jpg`), 폴더 정렬 순서, 줄바꿈 CRLF, **UTF-8** | 확장자 제외 / CP949(구형 프로그램 호환) |
| Q5 | 결과 저장 위치 | **사진 폴더 안**에 저장, 쓰기 실패 시 위치 선택 창 | 항상 위치 선택 / 로컬 바탕화면 |
| Q6 | 미분류가 남은 상태에서 저장 | 경고 후 허용(미분류는 두 목록 어디에도 넣지 않음) | 전부 분류해야 저장 가능 |
| Q7 | 키를 누르고 있을 때 | **1장만 처리**(자동 반복 무시) — 실수로 수십 장이 넘어가는 것 방지 | 누르고 있으면 연속 처리 |
| Q8 | 프로그램 이름 | `AOI Photo Sorter v1` (`programs/AOI_Photo_Sorter`) | 원하는 이름 |

## 2. 전체 구조

```
AOI_Photo_Sorter_v1.vbs               (기존 실행기 템플릿 그대로, 빠른 경로 → pythonw app.py)
└─ app.py  (Python 1개 프로세스)
   ├─ 메인 스레드: pywebview / WebView2 창
   │     · 브리지(pywebview.api)는 "폴더 선택 창, 저장 위치 선택, 탐색기 열기" 같은 드문 호출만 사용
   ├─ 로컬 서버 스레드: 127.0.0.1:<임의 포트>/<세션 토큰>/
   │     · 화면(HTML), 원본 사진, 썸네일, 진행 상황 동기화 — 자주 오가는 데이터는 전부 여기로
   ├─ 미리 읽기 스레드 8개: 네트워크 폴더 → RAM (우선순위 = 현재 위치에서 가까운 순)
   ├─ 썸네일 스레드 1~2개: RAM에 있는 원본으로 작은 썸네일 생성 (확인 화면용)
   └─ 자동 저장: 변경분을 1초 단위로 로컬 세션 파일에 원자적 기록
```

### 2-1. 왜 이 구조인가

- **기존 도구와 같은 실행·설치 구조**: 이미 검증된 VBS 빠른 실행 경로, 공용 venv, 영구 WebView2 프로필, 단일 실행 Mutex, 지연 import를 그대로 씁니다. 새 패키지가 없어 AOI Matcher가 설치된 PC에서는 설치가 몇 초 만에 끝납니다. `runtime.py` / `setup_env.py` / `constraints.txt`는 기존 두 프로그램과 **동일 파일**을 유지합니다.
- **사진을 pywebview 브리지로 보내지 않는 이유**: 브리지는 결과를 JSON 문자열로 만들어 WebView2 UI 스레드의 `ExecuteScript`로 넘깁니다. 사진 1장(수백 KB)을 base64(+33%)로 보내면 장당 수십 ms 동안 UI 스레드를 막고, 연타 중에 화면이 끊깁니다.
- **로컬 서버를 쓰는 이유와 안전장치**
  - 브라우저가 원본 바이트를 그대로 받아 **자체 디코더(화면 밖 스레드)**로 처리합니다. 가장 빠른 경로입니다.
  - 화면 HTML도 같은 서버에서 제공해 **같은 출처(same-origin)**로 만듭니다. 그래야 WebView2/Chromium의 "로컬 네트워크 접근" 제한이나 CORS 문제에 걸리지 않습니다.
  - 포트는 OS가 비어 있는 포트를 고르게(0번 바인딩) 해서, 예전 pywebview 고정 포트(42001) 충돌 같은 문제가 없습니다. 127.0.0.1만 열기 때문에 방화벽 창도 뜨지 않습니다.
  - 주소에 실행마다 바뀌는 **랜덤 토큰**이 들어가 다른 프로그램이 사진을 가져갈 수 없고, 사진은 **번호로만** 요청하므로 임의 경로 접근(경로 조작)이 불가능합니다.
  - `Cache-Control: no-store`: WebView2가 사진 수 GB를 디스크 캐시에 쌓지 않게 합니다.

## 3. 엔진 설계 (Python)

### 3-1. 폴더 스캔

- `os.scandir()` 1회로 목록을 읽습니다. Windows에서는 디렉터리 목록을 받을 때 크기·수정 시각이 함께 오므로 **파일마다 추가 네트워크 왕복이 없습니다**. `Path.glob()` + 파일별 `stat()`은 1만 번의 왕복이 생기므로 쓰지 않습니다.
- 확장자로 거르고, **탐색기와 같은 순서**로 정렬합니다(Windows `StrCmpLogicalW` 사용: `IMG_2` → `IMG_10` 순).
- 스캔하는 동안 화면에 "찾은 사진 N장"을 표시하고, 끝나면 바로 첫 사진을 준비합니다.
- 세션 중 폴더에 새로 생긴 파일은 반영하지 않습니다(작업 시작 시점의 목록으로 고정).

### 3-2. 미리 읽기 (핵심)

"사진 로딩" 단계에서 1만 장을 모두 읽고 시작하면, 4 GB(장당 400 KB 가정)를 다 읽을 때까지 수 분을 기다려야 하고 RAM도 부족합니다. 대신 **사용자가 보는 위치 기준으로 필요한 만큼만 앞서 읽습니다.**

```
           뒤쪽 유지(되돌리기용)           현재            앞쪽 미리 읽기
  ... ─── [−50 ……… −1] ─────────────── [ 0 ] ─── [+1 +2 … +200] ─── ... 나머지는 아직 안 읽음
  우선순위:      4                        1         2(+1~+10) → 3(+11~+200)
```

- 스케줄러가 현재 위치를 기준으로 "있어야 할 사진 목록"을 계산하고, 가까운 순서(앞쪽 우선)대로 읽기 스레드 8개에 나눠 줍니다. 위치가 바뀌면(넘기기, 되돌리기, 확인 화면에서 점프) 즉시 다시 계산합니다.
- **병렬 읽기**: 네트워크 폴더는 파일 하나를 여는 데 걸리는 지연(왕복 시간)이 병목입니다. 8개를 동시에 읽으면 지연이 겹쳐서 숨겨집니다. 예를 들어 파일당 50 ms인 느린 공유 폴더에서도 초당 약 160장을 읽을 수 있어, 사람이 넘기는 속도(초당 2~10장)보다 훨씬 빠릅니다.
- 파일은 `open → read(전체) → close`로 한 번에 읽습니다(크기를 미리 알기 때문에 요청 횟수가 최소).
- 읽기 실패(잠김, 일시적 끊김)는 0.2 s → 0.5 s → 1 s 간격으로 3회 재시도하고, 그래도 실패하면 "읽기 실패" 카드를 띄웁니다(아래 6장).
- 화면이 아직 준비되지 않은 사진을 요청하면 그 사진을 **맨 앞 순위로 올리고** 준비되는 즉시 응답합니다.

### 3-3. 메모리 관리

| 저장소 | 내용 | 한도(기본값) |
|---|---|---|
| RAM 원본 창 | 현재 위치 앞 200장 / 뒤 50장의 원본 바이트 | 384 MB + 128 MB, 개수와 용량 중 먼저 닿는 쪽. PC 메모리가 8 GB 이하이면 절반으로 자동 축소 |
| RAM 썸네일 | 본 사진마다 긴 변 192 px JPEG(약 8 KB) | 1만 장 ≈ 80 MB |
| 화면(JS) 디코딩 버퍼 | 다음 5장 / 이전 2장을 **화면 크기로 디코딩해 둔** ImageBitmap | 약 40~60 MB |

- 창 밖으로 나간 원본은 먼 것부터 버립니다. 1만 장을 끝까지 넘겨도 메모리는 일정하게 유지됩니다.
- 각 사진은 사용자가 지나갈 때 네트워크에서 **한 번만** 읽힙니다. 다시 읽는 경우는 확인 화면에서 오래전 사진을 크게 볼 때뿐입니다(장당 약 0.1초).
- 썸네일은 이미 RAM에 있는 원본으로 만들기 때문에 네트워크를 다시 쓰지 않습니다. JPEG는 Pillow의 축소 디코딩(`draft`)으로 장당 수 ms면 됩니다. Pillow는 디코딩하는 동안 GIL을 풀기 때문에 화면이나 서버를 방해하지 않습니다.

### 3-4. 사진 표시 원칙

- **원본 그대로 표시**합니다(재압축 없음). 판정용 사진이라 화질 손실을 만들지 않습니다.
- 브라우저가 표시할 수 없는 형식(TIFF)만 Python에서 PNG로 변환합니다.
- 화면 크기보다 큰 사진은 화면에 맞춰 고품질로 축소해 표시합니다. `F` 키로 100% 보기와 화면 맞춤을 전환하고, 휠로 확대·드래그로 이동합니다(확대할 때만 원본을 해당 1장만 다시 디코딩).

### 3-5. 진행 상황 자동 저장 / 이어하기

- 위치: `%LOCALAPPDATA%\AOI_Tools\Photo_Sorter\sessions\<폴더 경로 해시>.json`
- 내용: 폴더 경로, 파일 이름 목록, 라벨 문자열(`"OOXO.."` 1만 글자 ≈ 10 KB), 현재 위치, 시각
- 화면에서 바뀐 내용을 1초 단위로 묶어 Python에 보내고(순번을 붙여 순서 보장, 실패하면 재전송), Python은 **임시 파일 → 교체(os.replace)** 방식으로 기록합니다. 기록 도중 꺼져도 파일이 깨지지 않고, 잃는 것은 최대 1초분입니다.
- 같은 폴더를 다시 열면 "이전 작업 3,210 / 10,000 — 이어하기 / 새로 시작"을 묻습니다. 라벨은 **파일 이름 기준**으로 맞추므로, 그사이 추가된 사진은 미분류로, 삭제된 사진은 제외됩니다(개수 안내).

### 3-6. 결과 저장

- `<폴더명>_O.txt`, `<폴더명>_X.txt` 2개를 만듭니다. 한 줄에 파일 이름 1개씩, 폴더 정렬 순서대로 씁니다. 형식은 Q4 확정안을 따릅니다.
- 같은 이름의 파일이 이미 있으면 덮어쓸지 묻습니다.
- 임시 파일에 쓴 뒤 교체하므로, 네트워크가 끊겨도 반쯤 쓰인 결과 파일이 남지 않습니다.
- 저장이 끝나면 두 파일의 경로와 개수를 보여 주고 [폴더 열기]를 제공합니다.

| 앞쪽 미리 읽기 | 200장 / 384 MB | — |

## 4. UX 설계

### 4-1. 화면 흐름

```
[1. 시작] ──폴더 선택──▶ [2. 스캔·준비] ──첫 사진 준비──▶ [3. 분류] ──마지막 사진──▶ [4. 확인] ──저장──▶ [5. 완료]
    ▲  최근 폴더 / 이어하기                                    │  Esc: 일시정지 메뉴              │
    └──────────────────────────────────────────────────────────┴──────── 새 작업 ◀─────────────────┘
```

### 4-2. 화면 구성

**1. 시작**
```
 AOI Photo Sorter v1
 ─────────────────────────────────────────────
  [ 폴더 선택 (Ctrl+O) ]   또는 경로 붙여넣기: [ \\server\aoi\LOT123       ] [열기]

  최근 폴더
   \\server\aoi\LOT123      3,210 / 10,000 분류됨   [이어하기]
   \\server\aoi\LOT122      완료 (O 8,912 / X 1,088)
```
- UNC 경로는 폴더 선택 창보다 붙여넣기가 빠르기 때문에 경로 입력란을 함께 둡니다.

**3. 분류 (주 화면)** — 사진 영역을 최대로 하고, 필요한 정보만 위·아래 한 줄씩 둡니다.
```
 LOT123   1,234 / 10,000 (12.3%)   O 800   X 434            미리 읽기 +200 ●
 ████████░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░
                                                                            
                                                                            
                          (  사 진  — 화면에 맞춤  )                          
                                                                            
                                                                            
 IMG_001234.jpg                                  직전: IMG_001233.jpg → X
 O 양호   X 불량   ⌫ 되돌리기   ←/→ 이동   F 확대   Esc 메뉴
```
- O/X를 누르면 사진 테두리가 0.15초간 초록(O)/빨강(X)으로 반짝이고, 즉시 다음 사진으로 넘어갑니다. 효과는 투명도 애니메이션만 써서 화면 배치 계산이 일어나지 않습니다.
- "직전: … → X"는 방금 입력을 확인하는 용도입니다. 잘못 눌렀으면 바로 ⌫를 누르면 됩니다.
- 진행 막대는 분류 진행률을, 오른쪽 점(●)은 미리 읽기 상태를 나타냅니다(초록: 충분 / 노랑: 따라잡히는 중 / 빨강: 네트워크 대기).

**4. 확인**
```
 분류 결과   O 8,000   X 2,000   미분류 0
 [ O 목록 ] [ X 목록 ]        [ X만 빠르게 재확인 ]   [ O만 빠르게 재확인 ]
 ┌────┐┌────┐┌────┐┌────┐┌────┐┌────┐┌────┐┌────┐
 │    ││    ││ ▣  ││    ││    ││    ││    ││    │   ← 썸네일 (보이는 부분만 그림, 1만 장도 즉시 스크롤)
 └────┘└────┘└────┘└────┘└────┘└────┘└────┘└────┘
  클릭/Space: O↔X 전환   Enter: 크게 보기   방향키: 이동            [ 저장 (Ctrl+S) ]
```
- **빠르게 재확인**: 선택한 목록(보통 수가 적은 X)만 분류 화면과 같은 방식으로 다시 한 장씩 넘기며 O/X로 고칠 수 있습니다.
- 그리드는 보이는 줄만 화면에 그리는 가상 스크롤이라 1만 장이어도 가볍습니다.

**5. 완료**: 저장된 두 파일 경로와 개수, [폴더 열기], [새 작업]

### 4-3. 키 배치

| 화면 | 키 | 동작 |
|---|---|---|
| 분류 | `O` (보조 `1`) | O로 분류하고 다음 사진 |
| 분류 | `X` (보조 `2`) | X로 분류하고 다음 사진 |
| 분류 | `Backspace` / `Ctrl+Z` | 되돌리기: 이전 사진으로 돌아가 라벨 지움 |
| 분류 | `←` / `→` | 라벨은 그대로 두고 이전/다음으로 이동 (`→`는 분류된 범위 안에서만) |
| 분류 | `End` | 작업 위치(첫 미분류 사진)로 이동 |
| 분류 | `F`, 휠, 드래그 | 100% 보기 / 화면 맞춤, 확대, 이동 |
| 분류 | `Esc` | 일시정지 메뉴 (확인 화면으로, 처음으로) |
| 공통 | `Ctrl+S` | 확인 화면에서 결과 저장 |

- 이미 분류한 사진으로 돌아가 O/X를 다시 누르면 라벨을 덮어쓰고 다음으로 넘어갑니다.

### 4-4. 빠른 연타 안정성 규칙 (핵심)

1. **입력은 화면(JS)에서 즉시·동기 처리합니다.** 키 1번에 상태 변경 1번이며, Python 응답을 기다리지 않습니다. 키 이벤트는 단일 스레드 이벤트 루프에서 들어온 순서대로 처리되므로 순서가 뒤바뀌지 않습니다.
2. **보지 않은 사진은 분류되지 않습니다.** 현재 사진이 실제로 화면에 그려진 뒤(다음 프레임)부터 입력을 받습니다. 아직 준비되지 않았으면 입력을 **무시**하고 "불러오는 중"을 표시합니다. 입력을 쌓아 두었다가 나중에 적용하지 않습니다. 쌓아 두면 보지 않은 사진에 라벨이 붙기 때문입니다.
3. **키 누르고 있기(자동 반복)는 무시합니다** (`event.repeat`). 키를 꾹 눌러도 1장만 처리됩니다.
4. **한/영 상태, CapsLock, Shift에 영향받지 않습니다.** 글자 값(`event.key`) 대신 물리 키 위치(`event.code` = `KeyO`/`KeyX`)를 읽습니다. 한글 입력 상태에서 O를 누르면 'ㅐ'가 입력되는 문제가 생기지 않습니다.
5. **포커스 사고를 막습니다.** 분류 화면에는 입력란이 없고, 버튼은 키보드 포커스를 받지 않습니다(Space/Enter가 버튼을 누르는 사고 방지). 다른 창을 갔다 와도 포커스를 자동으로 복구합니다.
6. **다음 사진은 미리 디코딩해 둔 것으로 교체만 합니다.** 화면 크기로 미리 디코딩한 ImageBitmap을 캔버스에 그리기만 하므로 1프레임 안에 끝납니다. 화면 배치 계산(레이아웃)은 일어나지 않고, 숫자 표시는 프레임당 1번만 갱신합니다.
7. **저장은 화면을 막지 않습니다.** 변경분을 묶어 비동기로 보내고, 순번으로 순서를 보장하며, 실패하면 재전송합니다.

## 5. 성능 목표 (검증 기준)

| 항목 | 목표 |
|---|---|

## 6. 예외 처리

| 상황 | 동작 |
|---|---|
| 네트워크 일시 끊김 / 파일 잠김 | 3회 재시도 후 "읽기 실패" 카드(파일명, [R] 다시 시도). 이 상태에서도 O/X 분류는 가능하며, 확인 화면에 경고 아이콘 표시 |

| 결과 저장 실패 (쓰기 권한, 끊김) | 다른 위치 선택 창. 세션은 이미 자동 저장되어 있으므로 진행 손실 없음 |
| 분류 중 창 닫기 | 자동 저장 후 바로 종료(다음 실행 시 이어하기) |
| 중복 실행 | 기존 창을 앞으로 가져옴 (기존 단일 실행 Mutex) |

## 9. 위험 요소

|---|---|
| 사내 보안 프로그램이 127.0.0.1 통신을 막는 경우 (드묾) | 시작 시 자체 점검 후 안내 메시지 + 로그. 발생하면 WebView2 가상 호스트 매핑 방식으로 전환 검토 |
